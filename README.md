# User Service
Сервис для управления пользователями, ролями и аутентификацией

## Запуск
Для хранения данных используется PostgreSQL, запущенный в Docker:
```bash
docker run -d --name user-postgres -e POSTGRES_USER=postgres -e POSTGRES_PASSWORD=postgres -e POSTGRES_DB=user_db -p 5433:5432 -v user_pgdata:/var/lib/postgresql/data --restart unless-stopped postgres:16
```

Основной класс `UserserviceApplication` запускает сервис

При запуске приложения Flyway автоматически выполняет неприменённые миграции из `src/main/resources/db/migration`.  
Миграция `V1__init_schema` создаёт таблицы `users`, `roles`, `user_role` и добавляет начальные роли.  

Доступ к сервису - `http://localhost:9000`

## Эндпоинты
### Пользователи
* `POST /users` — Регистрация нового пользователя (автоматически выдаётся роль guest).
* `GET /users/{id}` — Получить профиль пользователя (включая роли).
* `GET /users?ids=...` — Получить список пользователей по их ID (батч-запрос для других сервисов).
* `PUT /users/{id}` — Обновить профиль.
* `DELETE /users/{id}` — Удалить пользователя.

### Аутентификация
* `POST /auth/login` — Логин по email и паролю (возвращает JWT-токен).

### Роли
* `GET /roles` — Получить список всех доступных ролей.
* `POST /roles/assign/{userId}/{roleId}` — Выдать роль пользователю.
* `DELETE /roles/remove/{userId}/{roleId}` — Отозвать роль у пользователя.

## Особенности
1. Для аутентификации используется JWT вместо хранения пользовательских сессий в базе данных. Время жизни токена — 1 час.
2. В JWT сохраняются ID пользователя и список его ролей.
3. Для пользователей используется UUID, для ролей — BIGSERIAL (Long).
4. При регистрации пользователю автоматически назначается роль guest.
5. AdminSeeder автоматически создаёт администратора при первом запуске и назначает ему все доступные роли. Данные для входа: admin@twitter.local / admin.
6. Для связи пользователей и ролей используется отдельная таблица user_role. Работа с ней реализована через JdbcTemplate.
